## 能力与边界

| 项目 | 当前状态 |
| --- | --- |
| 逐人约束、预算比较、修改后差异计算 | 已实现；同门店、同时间，1–50 人；到店自取、得来速、外送 |
| 多方案排名与理由、券预览（可领/已领/本店可用）、地址与可配送门店查询 | 已实现，全部只读；**模拟已验证，真实只读未验证** |
| 真实菜单、无糖饮品替换、官方核价 | 已接入；只处理接口明确支持的套餐与选项 |
| 门店券 | 能查询并有限尝试券商品；已验证单张当前券参与官方算价，未验证核销或多券 |
| 会员卡回本 | 支持给定卡费与每次节省额的计算；尚未接入实时卡权益 |
| 下单、领券、支付、积分兑换、取消 | 客户端拒绝调用相关写工具 |

仅比较已检查的有限候选。领券、下单、团餐为后续阶段，当前**未实现**；也不支持任意去冰去酱或自动长期口味记忆；无法保证过敏安全。真实菜单缺少的属性保持未知。[完整限制与常见问题](使用与接入.md#常见问题)

**原则：不知道，就明确说不知道。** 菜单没有说明辣度，就不能凭名称不带“辣”确认不辣；没有可确认的方案时，不会偷偷放宽预算或删掉要求。

## 验证分级
| 级别 | 范围 |
| --- | --- |
| 模拟已验证 | 多人（最多 50 人）、到店/得来速/外送参数映射、多方案排名与理由、券预览、地址脱敏、限流、写工具拒绝，均在本地回环模拟 MCP 服务器与合成数据上通过自动测试 |
| 真实只读未验证 | 上述新能力在真实账户、真实门店、真实地址上的行为（含 `currentPrice` 单位、地址列表顺序、未领取券是否出现在门店券里、同款不同饮料的核价），作者尚未使用真实 Token 运行 |
| 未实现 | 领券、下单、团餐、支付 |
上方 2026-10-17/10-19 的真实记录属于此前的单人/双人到店自取 v1 流程，不能当作新能力的真实验证。
