## 能力与边界

| 项目 | 当前状态 |
| --- | --- |
| 逐人约束、预算比较、修改后差异计算 | 已实现；同门店、同时间，1–50 人；到店自取、得来速、外送 |
| 多方案排名与理由、券预览（可领/已领/本店可用）、地址与可配送门店查询 | 已实现，只读；**模拟已验证，真实只读待验证** |
| 团餐（门店查询、助餐服务、促销提示、人均预算搭配、预约时间、订单摘要） | 已实现；**模拟已验证**；**真实只读待用户验证**（真实返回结构、满减满折是否体现在核价中均未验证）；团餐真实下单未开放 |
| 订单摘要、受控领券、受控下单（待支付）、订单状态查询 | 已实现；**模拟已验证**；**真实领券下单代码已具备但默认关闭、未经真实验证**（须用户自己打开开关并在终端亲手确认，见[启用指南](真实写操作启用指南.md)） |
| 真实菜单、无糖饮品替换、官方核价 | 已接入；只处理接口明确支持的套餐与选项 |
| 门店券 | 能查询并有限尝试券商品；已验证单张当前券参与官方算价，未验证核销或多券 |
| 会员卡回本 | 支持给定卡费与每次节省额的计算；尚未接入实时卡权益 |
| 支付、积分兑换、买卡、取消订单、抽奖、新建地址 | 永远不做，客户端拒绝调用相关工具 |

仅比较已检查的有限候选。团餐真实领券/下单未开放；也不支持任意去冰去酱或自动长期口味记忆；无法保证过敏安全。真实菜单缺少的属性保持未知。[完整限制与常见问题](使用与接入.md#常见问题)

**原则：不知道，就明确说不知道。** 菜单没有说明辣度，就不能凭名称不带“辣”确认不辣；没有可确认的方案时，不会偷偷放宽预算或删掉要求。

## 验证分级
| 级别 | 范围 |
| --- | --- |
| 模拟已验证 | 多人（最多 50 人）、到店/得来速/外送参数映射、多方案排名与理由、券预览、地址脱敏、限流、订单摘要、受控领券与下单（待支付）、重复与结果未知保护、订单查询、写工具拒绝，均在本机回环模拟 MCP 服务器与合成数据上通过自动测试 |
| 真实只读待用户验证 | v2 新增只读能力在真实账户、真实门店、真实地址上的行为（含 `currentPrice` 单位、地址列表顺序、未领取券是否出现在门店券里、同款不同饮料的核价、50 人合并数量核价、`query-order` 返回结构），作者尚未使用真实 Token 运行（v1 到店自取的真实只读见上文作者自述记录） |
| 真实领券下单默认关闭、未经真实验证 | 官方端点上的 `auto-bind-coupons`、`create-order` 的写通道代码已具备（四道门、终端亲手确认、金额与次数上限、紧急锁），默认关闭；只经本机网络桩验证门控与参数构造，没有任何真实领券或下单的验证，真实返回结构与超时后的真实状态未知。终端检查无法区分真人与被程序驱动的伪终端 |
| 未开放 | 团餐真实领券/下单（官方端点被代码拒绝，团餐规划与摘要仅模拟已验证、真实只读待用户验证） |
| 未实现 | 支付 |
上方 2026-10-17/10-19 的真实记录属于此前的单人/双人到店自取 v1 流程，不能当作新能力的真实验证。
## 已知限制
- 限流计数不跨进程共享。
- 订单账本依赖 POSIX 文件锁，仅支持 macOS／Linux。
- 摘要里的价格对应生成时刻的官方核价，过期或变化须重新确认。
