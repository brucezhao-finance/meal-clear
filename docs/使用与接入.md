# 使用与接入指南

[返回项目首页](../README.md)

所有命令均在仓库根目录执行。Python 3.9+，无需安装运行依赖。自然语言由使用该 Skill 的 Agent 理解，命令行读取结构化请求。

## 真实只读联调

环境变量 `MCD_MCP_TOKEN` 由用户在安全环境中设置。也支持`--token-file`读取已有本地文件，命令中只传路径，不传明文Token。没有凭证时仍可离线演示。

```sh
# 发现当前工具
python3 scripts/meal_clear.py inspect-tools

# 让用户确认实际门店，不能直接替用户选择技术测试店
python3 scripts/meal_clear.py stores --city 上海 --keyword 静安寺

# 编辑请求中的门店、预算、人数与要求后再运行
python3 scripts/meal_clear.py live-plan --request examples/live-request.json --save local-state/meal.json
```

`examples/live-request.json`使用上海静安寺工程测试门店1450002、单人无糖饮品、预算100元。它不是你的默认位置；使用前应改为自己确认的门店和要求。实时推荐通常共查询一次菜单、一次券、至多8个详情、至多3次报价，限于单人套餐结构。

修改后重新核价：

```sh
python3 scripts/meal_clear.py update --state local-state/meal.json --patch examples/patch-live-beef.json --save local-state/updated.json
```

该修改示例将A主食要求改为牛肉，并保留无糖、原预算和门店。没有新的可行方案时会明确失败，不使用旧报价冒充成功。

## 多人、得来速与外送（v2，只读）
v2 请求带 `schema_version=2`，支持 1–50 人与 `fulfillment`（`pickup`/`drive_thru`/`delivery`），返回带理由的多方案排名。示例见 `examples/request-multi3.json`、`request-multi6.json`、`request-multi50.json`（50 人，离线）、`request-drive-thru.json`、`request-delivery.json`（后两者为占位值，不含真实门店或地址）。
```sh
python3 scripts/meal_clear.py demo-multi
python3 scripts/meal_clear.py stores --city 上海 --keyword 静安寺 --be-type 5   # 得来速门店与 beCode
python3 scripts/meal_clear.py addresses                                         # 只显示地址序号
python3 scripts/meal_clear.py delivery-stores --address-index 1                 # 该地址可配送门店
python3 scripts/meal_clear.py coupons --request examples/request-multi3.json    # 只读券预览
python3 scripts/meal_clear.py live-plan --request 你的v2请求.json --top 3 --priority price
```
`--top`、`--priority` 仅用于 v2 请求。实时多方案单次运行最多 150 次工具调用，客户端另有每分钟 500 次的限流。团餐尚未实现。上述 v2 实时流程目前只经本地模拟服务器验证，真实账户只读验证未做。
## 确认式下单（模拟已验证，真实领券/下单默认关闭）
下面的命令只能在本机回环模拟服务上真正执行；对官方端点，真实写通道**默认关闭、未经真实验证**：开关未开时 `--execute` 在发出任何请求前被拒绝（退出码 4，提示“真实领券/下单尚未开放…”，含义是默认关闭，需你自己启用并亲自验证）。要在自己的终端打开并亲手确认，见 [真实写操作启用指南](真实写操作启用指南.md)。默认都是预演。
```sh
python3 scripts/meal_clear.py order-summary --request 你的v2请求.json --rank 1      # 生成订单摘要，记下完整摘要编号
python3 scripts/meal_clear.py order-claim --digest 摘要前缀                          # 预演：不领券
python3 scripts/meal_clear.py order-claim --digest 摘要前缀 --execute --confirm-digest 完整64位摘要编号
python3 scripts/meal_clear.py order-place --digest 摘要前缀                          # 预演：不下单
python3 scripts/meal_clear.py order-place --digest 摘要前缀 --execute --confirm-digest 完整64位摘要编号
python3 scripts/meal_clear.py order-status --digest 摘要前缀                         # 订单号只显示打码尾号
```
没有可领的券或不想领券，用 `order-summary --skip-claim`。每个 `--execute` 之前，都应由你亲自看过完整摘要并明确同意。价格变化或摘要过期时退出码为 3，需对新摘要重新确认。结果未知（退出码 6）时不要重试，先在 App 订单列表核实。订单创建后是待支付状态，本工具不会付款，也不会取消订单。退出码见[数据契约](../references/data-contract.md)。端到端演示：`python3 tests/e2e_order_flow.py`（模拟服务，不联网）。
## 离线文件和会话

```sh
python3 scripts/meal_clear.py plan --request examples/request.json --catalog examples/demo-catalog.json --save local-state/demo.json
python3 scripts/meal_clear.py update --state local-state/demo.json --patch examples/patch-beef.json --catalog examples/demo-catalog.json
python3 scripts/meal_clear.py break-even --fee 1400 --saving 200
```

金额参数为整数分。最后一个命令只计算固定每次省2元、卡费14元的回本次数7次，不表示今天存在该卡或该优惠。

CLI退出码：0有推荐/查询或计算完成；2无可确认推荐（未知、超预算、核价失败等业务状态）；1输入、认证或协议错误；order-* 命令另有 3（需重新确认）、4（安全门拒绝）、5（重复）、6（结果未知）、7（超过金额/次数上限）、8（写锁定）。用`--json`获得结构化结果。

状态文件保存请求、脱敏结果和工具耗时，权限为600，不保存Token或券码；仍可能包含你的口味偏好，不应上传公开仓库。

## 常见问题

- **说不辣却没有结果？** 当前菜单/详情通常不完整声明辣度；不能凭“没有辣字”确认不辣。程序拒绝强行推荐，模拟菜单仅用来验证这条逻辑。过敏安全不在能力范围。
- **为什么有官方总价，运费拆分却未知？** 到店自取实测返回整单`price`与`productPrice`，部分费用字段为空。采用官方整单应付，拆分保持未知，不擅自填0。
- **为什么不叫全网最便宜？** 只搜索有限的单人套餐和少量券商品，没有覆盖全菜单、所有拆分与跨渠道活动；多人排名只在已检查的候选里排。
- **能自动下单吗？** 不会自动。领券和下单只能走确认式流程，逐步由你明确同意，且目前只在本机回环模拟服务上经过验证；真实环境领券/下单默认关闭、未经真实验证，需你自己打开开关并在终端亲手确认。客户端永远拒绝取消订单、积分消费、抽奖等工具，也不会自动付款。
- **套餐没覆盖？** 目前仅支持每个必选轮次选一件、有完整默认项、含主食和饮品的单人套餐。不会把单个薯条当作一餐。
- **能自动去冰去酱吗？** 暂不支持任意特制修改；只保留返回的默认特制和明确支持的无糖饮料替换。不能用备注伪造能力。
- **报401/403或网络失败？** 检查授权环境；认证错误不重试。暂时性只读失败最多额外重试2次，失败后不会伪造结果。
- **会记住我的口味吗？** 本地会话可保留并修改，尚无自动长期偏好记忆。

## 已知限制
- 限流计数在单个进程内，不跨进程共享；同时开多个进程会各自计数。
- 账本依赖 POSIX 的文件锁，仅支持 macOS／Linux。
- 真实官方 `calculate-price` 对 50 人合并数量的行为未验证。
## 开发与维护

```sh
python3 -m unittest discover -s tests -v
```

业务逻辑位于 `scripts/meal_clear/`，包括约束组合、只读 MCP、实时菜单适配和 CLI。`references/` 提供[请求契约](../references/data-contract.md)和[验收场景](../references/evaluation-cases.md)。`examples/` 为模拟输入、修改与演示输出；`verification/` 为脱敏验证记录（仅在源码仓库中，不在发布包内）；`agents/openai.yaml` 是 Agent 界面元数据。

保持 Python 3.9 兼容和零运行依赖。修改后运行离线回归；涉及真实接口时，应记录日期、门店、数据范围及未验证分支，不能把历史回放当成当前报价。新增能力还须遵守 [项目开发规则](../AGENTS.md)。
