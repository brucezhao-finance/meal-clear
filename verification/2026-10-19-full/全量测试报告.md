## 5. 不适用或仍需外部条件的点

- 不支持的外送、超过2人、任意去冰/去酱、自动领券/下单/支付/兑换：测的是正确拒绝，不能测试成成功功能。

- 过敏及医疗饮食安全不在声明能力内；已检查不能误承诺，不能用测试证明食物安全。

- 当前只有一个可用账户：无法声称多账户、全部券资产/失效条件、多券叠加和全部门店已做真实验证；不适用券负向使用模拟服务。

- 未验证全部操作系统、所有Python版本、所有Agent客户端的自动安装/触发，也未做独立Agent盲测或真实用户易用性统计。

- 没有真实领券、买卡、下单、支付或取餐；不把ready等同购买成功。

因此本报告保证的是：**当前实现的可达代码和本清单内可执行测试点均有执行证据，已知失败已修复**；不作“任何未来输入、任何账号环境永不失败”的承诺。

无需依赖的测试：

```sh
python3 -m unittest discover -s tests -v
python3 verification/2026-10-19-full/run_full.py
python3 verification/2026-10-19-full/run_mutations.py
```

要采集分支覆盖，另建隔离测试环境（Skill本身仍零运行依赖）：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install coverage==7.10.7
.venv/bin/python verification/2026-10-19-full/run_full.py --coverage
```

本次实际使用临时虚拟环境，没有全局pip安装；未升级pip。真实两城测试可用：

```sh
python3 verification/2026-10-19-full/run_live.py --token-file <本机凭证文件>
```

凭证只在内存中使用，默认复跑输出到gitignored的local-state/full-live-replay；复跑价格和菜单可以变化。离线run_full会重写本验收目录的最终日志与汇总，若需保留快照，先复制本目录到verification下新建同级目录，再执行复制后的脚本。测试过程含模拟失败与变异，不能把这些刻意失败的日志当作最终版本仍失败。
