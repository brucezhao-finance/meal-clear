## 1. 测试怎么设计

我先读SKILL.md与数据契约，再设计三组任务，预先人工计算金额和失败预期，最后执行，不把“进程退出了”直接算通过。

- **正常任务：** 两人都不辣、无糖；临时只改B必须牛肉；换饮料后重新核价。
- **边界任务：** 预算差1分、恰好等于预算、未知属性、新卡费、费用缺失、换店和资料来源。
- **失败任务：** 损坏JSON、损坏菜单、三人超范围、重复id、未知用户修改、认证与连续网络错误。

模拟数据与官方数据彻底分开。真实测试店是上海静安寺1450002，工程测试自行选取，不替用户选择就餐地点。官方只读调用不产生订单，不领券、不买卡、不支付、不兑换；有券算价也不核销券。

## 2. 离线完整流程

模拟菜单另行设计：鸡肉21.50元、牛肉29元；便宜但辣度未知12元、明确辣味18元；另有13元餐费加12元新卡的组合。**这些全部虚构，不能作为购买依据。**

1. 两人不辣、无糖，偏好鸡肉，预算60元：输出21.50+21.50=**43元**。
2. 只改B必须牛肉：输出21.50+29=**50.50元**，增加7.50元；A的约束、预算与门店不变。
3. 预算43元：通过；预算42.99元：拒绝且保持原预算。
4. 只有辣度未知或明确辣味的餐：拒绝，不因便宜就冒充满足不辣。
5. 会员条件算账：13+12=25元，不能宣传成只需13元。
6. 缺费用、换店、修改后无解：不补零、不复用旧菜单、不编价差。

完整27项见[过程文档第二节](完整测试过程.md#2-独立设计数据与任务)；每项保存输入JSON、实际命令、退出码、标准输出、错误输出、耗时和断言结果。

## 3. 两类缺陷与修复

### 缺陷A：损坏的导入菜单会导致异常堆栈

**首轮3个场景复现：** `offers=[null]`、`items=[null]`、`facts=[]`。

表层报错为 `AttributeError: 'NoneType' object has no attribute 'get'` 或 `'list' object has no attribute 'values'`。根因是校验函数在确认对象/列表类型前就调用`.get()`/`.values()`，并非用户预算或网络问题。

修复：在套餐、餐品列表与证据集合入口检查容器类型，再做业务校验，返回受控InputError；没有用笼统捕获所有异常掩盖错误。新增回归覆盖5种损坏容器。修复后O21–O23输出结构化错误、退出码1，无异常堆栈。

[O21修复前](before-fix/O21.json) / [修复后](outputs/O21.json)；[O22前](before-fix/O22.json) / [后](outputs/O22.json)；[O23前](before-fix/O23.json) / [后](outputs/O23.json)。

### 缺陷B：早餐“组合”被候选筛选漏掉

真实首轮取到90条早餐菜单，但筛选器仅认“件套、套餐、单人餐”，不认“组合”。普通非会员的“芝芝火腿扒堡组合”因此没有进入详情查询；无糖单人与双人任务都没有推荐。

进一步实际查询详情，确认该组合包含主食、饮品，且存在官方无糖可乐选项。这证明是筛选遗漏，不能解释为门店确实没有可行餐品。

修复：把“组合”纳入主食候选名筛选；仍检查完整主食饮品结构，继续过滤附带会员条件的项目。新增回归确认普通组合会进入详情核验、会员条件组合不会被顺带放开。

## 5. 耗时、成本与隐私

单店正常真实选餐L03、L05、L07、L08耗时分别为4.98秒、5.18秒、7.10秒、5.30秒。样本很小、同一环境，不作为性能承诺。每次真实规划依旧最多6个普通套餐详情、2个券商品详情、3次报价；本次修复没有放大搜索上限。

离线测试没有安装依赖、没有启动额外模型服务；故障测试使用模拟传输。真实测试沿用已有本机凭证，仅在内存中使用，命令记录替换凭证路径；会话状态位于gitignored的local-state目录，权限600。公开技术记录不含Token、券码、会员标识或完整账户回包。

## 6. 还不能下的结论

- 尚未做跨店、多账户、多日期、午晚餐全覆盖；这次主要验证早餐时段。
- 只确认单张实际券的正向算价，没有真实验证所有不适用券、多券、领取或核销。
- 过敏/医疗饮食安全未验证；当前名称标签不能证明。
- 未做独立Agent盲测、跨客户端自动安装/触发测试、自然语言准确率统计或真实用户体验实验。本次是当前Agent依据Skill规则构建请求并完成任务。
- 没有下单、支付或取餐测试，不能把ready理解成购买成功。
- 仍是有限候选搜索，不保证全局最低价、库存或到店即取。

## 7. 如何复现

在项目根目录执行：

```sh
python3 -m unittest discover -s tests -v
python3 verification/2026-10-19-acceptance/run_offline.py
python3 verification/2026-10-19-acceptance/run_protocol.py
```

真实测试按[完整过程第四节](完整测试过程.md#4-真实只读执行)的L01–L08命令运行，将占位符替换为自己的凭证文件；或者配置MCD_MCP_TOKEN后去掉token-file参数。真实请求里的工程店需先重新查询确认；不要拿测试店当个人默认位置。复跑真实接口时价格与可行餐品可能变化，不能把本报告固定金额当作永久通过断言。

离线脚本会重写本目录的O组输出与汇总，并在local-state/acceptance-20261019创建模拟会话；若要保留原始验收快照，请先复制本验收目录到verification下一个新的同级目录，再执行复制目录内的脚本。
