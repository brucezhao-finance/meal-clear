# 麦麦明白点 meal-clear

**麦麦点餐，改一句就明白。**

> **“麦麦” = 大家对麦当劳（McDonald's）的昵称。** 1–50 个人一起点、要求各不同、预算有限，这个 Skill 帮你逐人核对，在到店自取、得来速、外送、团餐中给出带理由的多方案排名；改一句也只重算该改的部分。**默认只读，领券/下单需你逐步确认（模拟已验证；真实领券/下单默认关闭、未经真实验证）。**

![麦麦明白点总流程：你说一句、逐人检查、比较方案、给出报价、改一句只重算B，价格从模拟38元变为43元，默认只读，领券下单需你逐步确认](docs/images/01-overview.svg)

体验（零依赖、免 Token、不联网）：`python3 scripts/meal_clear.py demo`（两人改一句）· `python3 scripts/meal_clear.py demo-multi`（3 人多方案排名）· `python3 scripts/meal_clear.py demo-group`（20 人团餐，模拟数据）

> 图中商品与价格均为**模拟数据**。**非麦当劳官方产品，参赛作品。**

## 适合谁

- 几个人聚餐、同事团餐，想让每个人各自满足忌口和偏好、同时控制总预算的人。
- 想把“带约束的选餐与比价”接入自己的 Agent、并希望默认只读、写操作有明确门槛的开发者。
- 目前的结果来自模拟数据和自动测试；真实账户上的新增能力、真实领券/下单均未经真实验证（见下文“能力与边界”）。

## 多方案排名
![多方案排名：模拟数据，3人预算70元，第1名52.50元依赖券，第2名53.00元不依赖券，第3名53.50元偏好最多；排序规则与检查范围](docs/images/05-ranking.svg)
`demo-multi` 的输出节选（模拟数据，非真实菜单与价格）：
```text
名次 | 总价 | 比第1名 | 偏好 | 券依赖
1 | ¥52.50 | — | 1/3 | 1
2 | ¥53.00 | +¥0.50 | 0/3 | 0
3 | ¥53.50 | +¥1.00 | 2/3 | 1
共检查 105 个整单候选（搜索空间 392 种），结果是已检查方案中的排名，不是全局最优。
```
排序规则：先过门槛（每人硬要求全部已核实且预算内），再按总价升序、偏好数降序、新购卡升序、券依赖升序、方案编号排列；每个名次附理由。未领取的券不计入报价。请求格式见 [数据契约](references/data-contract.md)，外送与得来速写法见 [examples/request-delivery.json](examples/request-delivery.json)、[examples/request-drive-thru.json](examples/request-drive-thru.json)。

## 多人（最多 50 人）
人多时，硬要求和偏好完全相同的人会归为一个“同质组”，按“整组吃什么 × 几份”搜索，组内最多 2 种不同套餐、每组保留前 48 种分配；超过 12 人时文本报告按组汇总（`--detail` 展开逐人，`--json` 永远是逐人完整数据）。离线示例（模拟数据，50 人 4 组）：
```bash
python3 scripts/meal_clear.py plan --request examples/request-multi50.json --catalog examples/demo-catalog-multi.json
```
这是对已检查组合的排名，不是全局最优；50 人的耗时与核价次数见[性能记录](docs/性能记录.md)（合成数据、本机离线基准）。真实环境下 50 人的官方核价行为（数量合并是否与逐行等价）尚未验证。

## 团餐（模拟已验证，团餐真实下单未开放）
![团餐流程：地址、可配送门店、促销与助餐服务、人均预算搭配、排名与理由、订单摘要；模拟数据；团餐真实下单未开放](docs/images/08-group-meal.svg)
团餐用 `fulfillment.type=group`，需给出人数、总预算或人均预算（二选一，人均按向下取整折算，余数留在总预算内）、地址序号、门店与 beCode、助餐服务编码，可选预约时间（`yyyy-MM-dd HH:mm`）。先 `delivery-stores --address-index N --be-type 6` 选店，再 `group-info --request 团餐请求.json` 看助餐服务与促销；助餐服务编码必须由你从列表里选定，程序不会替你采用官方默认项。促销规则只作提示，价格一律以官方 `calculate-price` 核价为准。离线体验（模拟数据）：`python3 scripts/meal_clear.py demo-group`，输出节选见 [examples/demo-output.md](examples/demo-output.md)。**团餐真实下单未开放**：官方端点上的团餐领券/下单被代码直接拒绝，本机回环模拟服务可演练完整流程。
## 确认式下单（模拟已验证，真实领券/下单默认关闭）
![确认式下单流程：预览比价排名、订单摘要、你确认领券、领券、重新核价、你再确认下单、创建待支付订单、你自己付款；模拟数据，真实写默认关闭](docs/images/06-confirm-flow.svg)
选定方案后，Agent 会生成**订单摘要**（餐品、数量、应付总额、将领的券、有效期、摘要编号），完整展示后**等你明确同意**才领券（一键领全部、无法逐张选择、不可撤销）；领券后重新查券、重新核价，价格或内容变了就回到新摘要重新确认；再次得到你的同意才创建**待支付订单**，付款由你自己完成。命令：`order-summary` → `order-claim` → `order-place` → `order-status`，默认都是预演，真正执行要加 `--execute --confirm-digest 完整摘要编号`。详细步骤见 [SKILL.md](SKILL.md)。官方端点的真实写通道**默认关闭、未经真实验证**，启用与紧急关闭见 [真实写操作启用指南](docs/真实写操作启用指南.md)。

## 安全闸门
![安全闸门：必须带执行开关、摘要编号匹配且未过期、写目标是本机回环地址；永远拒绝取消订单、新建地址、抽奖等；真实官方写默认关闭，开启后还需终端亲手确认和金额次数上限](docs/images/07-safety-gates.svg)
四道门缺一不可：① `--execute`；② 与记录匹配且未过期的完整摘要编号；③ 写目标固定为本机回环或官方端点；④ 真实写开关打开 + 你在自己的终端里亲手输入确认短语 + 金额与 24 小时次数上限。写前先落本地账本，失败或结果未知时绝不自动重试，并锁定该篮子 24 小时，另有 `write-lock` 紧急锁。官方写通道**默认关闭、未经真实验证**，所以现在不要把它当作已经能在真实环境领券或下单的功能。

**已知局限：** 终端检查只能证明有交互终端，无法区分真人和被程序驱动的伪终端；防线还包括 Agent 禁令（不得代确认、不得绕过终端、不得索要 Token）、开关由你自己打开、上限和紧急锁。

## 改一句，不重来

![改一句前后对比：A保持模拟鸡肉组合19元，B从鸡肉组合19元换成牛肉组合24元，合计从38.00元变为43.00元，增加5元](docs/images/03-change-one-line.svg)

只改 B，其他条件（不辣、无糖、预算）保留；旧报价不会被当作新结果。

## 它不会做什么

![安全边界：默认只读，会逐人核对和算差价；不会做未经确认的领券下单、自动付款、买卡积分兑换、取消订单](docs/images/04-safety-boundary.svg)

不知道，就明确说不知道。仅比较已检查的有限候选。

## 安装与依赖

- Python ≥ 3.9，**零运行依赖**。
- **平台：** 领券/下单的本地账本依赖 `fcntl`，仅支持 macOS/Linux；`demo`、`demo-multi`、`demo-group`、规划与排名等只读功能不依赖该账本。账本相关命令（`order-summary`、`order-claim`、`order-place` 等）在不支持的平台上会直接拒绝执行。
- 把整个 `meal-clear` 目录放进 Agent 的 Skill 位置，或使用发布包 `dist/meal-clear.skill`（由 `python3 scripts/build_skill.py` 生成）。
- 真实菜单模式需自行配置凭证，详见 [使用与接入](docs/使用与接入.md)。

## 能力与边界

| 项目 | 当前状态 |
| --- | --- |
| 逐人约束、预算比较、修改后差异计算 | 已实现；同门店、同时间，1–50 人（≤6 人逐人搜索；7–50 人按同质组搜索）；到店自取、得来速、外送、团餐（团餐真实下单未开放） |
| 多方案排名与理由、券预览（可领/已领/本店可用） | 已实现，只读；**模拟已验证，真实只读待用户验证** |
| 真实菜单、无糖饮品替换、官方核价 | 已接入；只处理接口明确支持的套餐与选项 |
| 门店券 | 能查询并有限尝试券商品；已验证单张当前券参与官方算价，未验证核销或多券 |
| 会员卡回本 | 支持给定卡费与每次节省额的计算；尚未接入实时卡权益 |
| 团餐（人数多、按人均或总预算、需选助餐服务、可预约时间） | 已实现，只读规划与订单摘要：**模拟已验证**；**真实只读待用户验证**（团餐门店、促销、助餐服务的真实返回结构未验证）；**团餐真实下单未开放**：官方端点上团餐领券/下单一律被代码拒绝（退出码 4），仅在本机回环模拟服务上可演练 |
| 订单摘要、受控领券、受控下单（待支付）、订单查询 | 已实现；**模拟已验证**（本机回环模拟服务）；**真实只读待用户验证**（订单查询等只读）；**真实领券下单代码已具备但默认关闭、未经真实验证**（须你自己打开开关并在终端亲手确认，见[启用指南](docs/真实写操作启用指南.md)） |
| 支付、积分兑换、买卡、取消订单、抽奖、新建地址 | 永远不做，客户端拒绝调用相关工具 |

仅比较已检查的有限候选，**不承诺全网最低价**。团餐的真实领券/下单未开放（团餐在模拟服务上已验证，真实只读待用户验证）；也不支持任意去冰去酱或自动长期口味记忆；无法保证过敏安全。验证分三档：**模拟已验证 / 真实只读待用户验证 / 真实领券下单代码已具备但默认关闭、未经真实验证**。真实菜单缺少的属性保持未知。[完整限制与常见问题](docs/使用与接入.md#常见问题)

## 验证与维护

```sh
python3 -m unittest discover -s tests -v
```

**550 项离线测试**（含本地回环模拟 MCP 服务器）覆盖金额精度、卡费、未知约束、多人排名、50 人同质组、取餐方式、隐私脱敏、限流、券预览、摘要与账本、受控领券/下单（模拟服务与官方路径网络桩）、重复与未知结果保护、换店报价失效、官方费用矛盾、协议解析、文件安全、文档一致性与写工具拒绝。测试不需要网络和真实账户。另有本次验收的 [27 项命令行场景与 5 项故障测试](https://github.com/brucezhao-finance/meal-clear/blob/main/verification/2026-10-19-acceptance/完整测试过程.md)。
