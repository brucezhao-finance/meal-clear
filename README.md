# 麦麦明白点 meal-clear

**麦麦点餐，改一句就明白。**

> **“麦麦” = 大家对麦当劳（McDonald's）的昵称。** 1–50 个人一起点、要求各不同、预算有限，这个 Skill 帮你逐人核对，在到店自取、得来速、外送中给出带理由的多方案排名；改一句也只重算该改的部分。**默认只读，领券/下单需你逐步确认（模拟已验证，真实环境未开放）。**

![麦麦明白点总流程：你说一句、逐人检查、比较方案、给出报价、改一句只重算B，价格从模拟38元变为43元，默认只读，领券下单需你逐步确认](docs/images/01-overview.svg)

体验（零依赖、免 Token、不联网）：`python3 scripts/meal_clear.py demo`（两人改一句）· `python3 scripts/meal_clear.py demo-multi`（3 人多方案排名）

## 多方案排名
![多方案排名：模拟数据，3人预算70元，第1名52.50元依赖券，第2名53.00元不依赖券，第3名53.50元偏好最多；排序规则与检查范围](docs/images/05-ranking.svg)
`demo-multi` 的输出节选（模拟数据，非真实菜单与价格）：
```text
名次 | 总价 | 比第1名 | 偏好 | 券依赖
1 | ¥52.50 | — | 1/3 | 1
2 | ¥53.00 | +¥0.50 | 0/3 | 0
3 | ¥53.50 | +¥1.00 | 2/3 | 1
共检查 105 个整单候选（搜索空间 392 种），结果是已检查方案中的排名，不是全局最优。
```
排序规则：先过门槛（每人硬要求全部已核实且预算内），再按总价升序、偏好数降序、新购卡升序、券依赖升序、方案编号排列；每个名次附理由。未领取的券不计入报价。请求格式见 [数据契约](references/data-contract.md)，外送与得来速写法见 [examples/request-delivery.json](examples/request-delivery.json)、[examples/request-drive-thru.json](examples/request-drive-thru.json)。

## 多人（最多 50 人）
人多时，硬要求和偏好完全相同的人会归为一个“同质组”，按“整组吃什么 × 几份”搜索，组内最多 2 种不同套餐、每组保留前 48 种分配；超过 12 人时文本报告按组汇总（`--detail` 展开逐人，`--json` 永远是逐人完整数据）。离线示例（模拟数据，50 人 4 组）：
```bash
python3 scripts/meal_clear.py plan --request examples/request-multi50.json --catalog examples/demo-catalog-multi.json
```
这是对已检查组合的排名，不是全局最优；50 人的耗时与核价次数见仓库内的性能记录。真实环境下 50 人的官方核价行为（数量合并是否与逐行等价）尚未验证。

## 确认式下单（模拟已验证，真实环境未开放）
![确认式下单流程：预览比价排名、订单摘要、你确认领券、领券、重新核价、你再确认下单、创建待支付订单、你自己付款；模拟数据，真实环境未开放](docs/images/06-confirm-flow.svg)
选定方案后，Agent 会生成**订单摘要**（餐品、数量、应付总额、将领的券、有效期、摘要编号），完整展示后**等你明确同意**才领券（一键领全部、无法逐张选择、不可撤销）；领券后重新查券、重新核价，价格或内容变了就回到新摘要重新确认；再次得到你的同意才创建**待支付订单**，付款由你自己完成。命令：`order-summary` → `order-claim` → `order-place` → `order-status`，默认都是预演，真正执行要加 `--execute --confirm-digest 完整摘要编号`。详细步骤见 [SKILL.md](SKILL.md)。

## 安全闸门
![安全闸门：必须带执行开关、摘要编号匹配且未过期、写目标是本机回环地址；永远拒绝取消订单、新建地址、抽奖等；真实官方地址一律拒绝](docs/images/07-safety-gates.svg)
三道门缺一不可：`--execute`、与记录匹配且未过期的摘要编号、回环目标。写前先落本地账本，失败或结果未知时绝不自动重试。真实官方地址在当前阶段一律拒绝写请求，所以**现在不能用它在真实环境领券或下单**。

## 改一句，不重来

![改一句前后对比：A保持模拟鸡肉组合19元，B从鸡肉组合19元换成牛肉组合24元，合计从38.00元变为43.00元，增加5元](docs/images/03-change-one-line.svg)

只改 B，其他条件（不辣、无糖、预算）保留；旧报价不会被当作新结果。

## 它不会做什么

![安全边界：默认只读，会逐人核对和算差价；不会做未经确认的领券下单、自动付款、买卡积分兑换、取消订单](docs/images/04-safety-boundary.svg)

不知道，就明确说不知道。仅比较已检查的有限候选。

## 能力与边界

| 项目 | 当前状态 |
| --- | --- |
| 逐人约束、预算比较、修改后差异计算 | 已实现；同门店、同时间，1–50 人（≤6 人逐人搜索；7–50 人按同质组搜索）；到店自取、得来速、外送 |
| 多方案排名与理由、券预览（可领/已领/本店可用） | 已实现，只读；**模拟已验证，真实只读待验证** |
| 真实菜单、无糖饮品替换、官方核价 | 已接入；只处理接口明确支持的套餐与选项 |
| 门店券 | 能查询并有限尝试券商品；已验证单张当前券参与官方算价，未验证核销或多券 |
| 会员卡回本 | 支持给定卡费与每次节省额的计算；尚未接入实时卡权益 |
| 订单摘要、受控领券、受控下单（待支付）、订单查询 | 已实现；**模拟已验证**（本机回环模拟服务）；**真实只读待验证**（订单查询等只读）；**真实领券/下单未开放**（官方端点一律拒绝，计划 P2 由作者亲自验证） |
| 支付、积分兑换、买卡、取消订单、抽奖、新建地址 | 永远不做，客户端拒绝调用相关工具 |

仅比较已检查的有限候选，**不承诺全网最低价**。团餐为后续阶段，**当前未实现**；也不支持任意去冰去酱或自动长期口味记忆；无法保证过敏安全。验证分三档：**模拟已验证 / 真实只读待验证 / 真实领券下单未开放**。真实菜单缺少的属性保持未知。[完整限制与常见问题](docs/使用与接入.md#常见问题)
