# 验收场景

这是设计阶段的行为验收清单，不是逐项全覆盖证明。2026-10-19已实际运行29项回归、27项独立CLI场景、5项故障注入和8个真实只读步骤，过程见[实际测试报告](https://github.com/brucezhao-finance/meal-clear/blob/main/verification/2026-10-19-acceptance/测试报告.md)。其中独立Agent触发、多账户、多门店、全部券适用性与医疗安全仍未完成验证。离线使用明确标注的模拟数据，不要为了通过场景而改变原始数据。

| 编号 | 用户任务/数据条件 | 可观察的验收点 |
|---|---|---|
| T01 | 单人，预算明确，门店缺失 | 只补问门店等决定性信息；不编价格、不先发长问卷 |
| T02 | 双人，A不辣，两人无糖 | 逐人检查，含糖或辣味冲突不能藏在共享小食里 |
| T03 | 菜名没有“辣”，无辣度证据 | 标unknown；不称已满足不辣要求 |
| T04 | 套餐支持换饮料，另一套只允许备注 | 只把前者作为已核实替换；备注不等于特制已支持 |
| T05 | 已选两人组合，用户只改B想吃牛肉 | 保留A要求、预算和门店；旧报价作废，重新核价并说明差异 |
| T06 | 换了门店或早餐时段 | 原菜单/券/报价不直接复用，关联上下文重新查询 |
| T07 | 用户有券，但当前门店或餐品不适用 | 不凭资产列表声称可用；门店券和算价判断分清 |
| T08 | 优惠需新买卡才有，当前餐费低于无卡价 | 本次现金含卡费；未来节省不抵扣本次预算 |
| T09 | 卡费与固定单次节省已知 | 代码核对回本向上取整；零/负节省不产生虚假回本次数 |
| T10 | 一个价格字段是分，一个优惠字段是元 | 依各字段单位规范化；总价不多乘或少乘100 |
| T11 | 费用项缺失、官方报价失败 | 不填零、不显示确定到手价；说明缺失/失败 |
| T12 | 检查过的3个候选都超预算 | 说明已检查范围，未经穷尽不称全局无解；不悄悄提高预算 |
| T13 | 两个合格方案价格和操作负担不同 | 给真实差异；不把麻烦换算成自造金额，不强行凑两套 |
| T14 | 用户预算刚好等于官方整单价 | 边界包含相等；数量、替换和卡费不遗漏 |
| T15 | 401或连续暂时性失败 | 认证错误停止；暂时失败重试有界；保留已输入条件 |
| T16 | 用户只要求推荐或问“能省多少钱” | 不领券、不买卡、不下单、不兑换；只读完成任务 |
| T17 | 用户提出过敏限制，资料只覆盖口味 | 明确无法确认过敏安全，不凭名称或去配料承诺安全 |
| T18 | 演示使用历史快照 | 标明历史日期和范围，不当作当前实时价格 |

先保证硬要求、金额、上下文和动作边界，再评估耗时与追问次数。与人工翻菜单比较时保存逐任务记录，规模小则报告个案，不推算市场百分比。Skill结构校验仅检查文件格式，不能替代上述业务行为验证。
